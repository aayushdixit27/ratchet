# PART 1 — REPLAY  (`https://qa.replay.io/api/v1/openapi.json`)

| We assumed | Actually |
|---|---|
| `https://api.replay.io/qa/v1` | **`https://qa.replay.io`**, paths under `/api/v1/` |
| `X-API-Key` | **`Authorization: Bearer lqa_...`** (token starts `lqa_`) |
| one-shot `scan(url)` | **project-scoped and asynchronous** |

```
POST  /api/v1/projects                  create project + start exploration on a URL
GET   /api/v1/projects/{id}/status      poll: counts of explorations/journeys/runs/bugs
GET   /api/v1/projects/{id}/bugs        list bugs
GET   /api/v1/bugs/{bug_id}             detail: analysis, evidence, reproduction_steps
PATCH /api/v1/bugs/{bug_id}             "mark it fixed after applying a fix"
```
Also: `POST /api/v1/projects/{id}/explorations`, `GET /api/v1/projects/{id}/reverse-proxy`, `POST /api/v1/projects/{id}/report-missing-bug`, `GET /api/v1/journeys/{id}`, `GET /api/v1/explorations/{id}`.

**Field mapping — their names differ from our dataclass:**
```
Bug.id         <- bug_id
Bug.title      <- title
Bug.root_cause <- analysis      # NOT "root_cause". This is the string we EMBED,
                                # so it matters most. If thin, concatenate
                                # analysis + expected_behavior + actual_behavior.
Bug.repro      <- reproduction_steps
Bug.selector   <- None unless parseable from analysis. Do NOT invent one.
Bug.bug_class  <- ours, derived. `polish_category` is a useful prior; keep in raw.
Bug.raw        <- severity, status, replay_recording_id, polish_category, everything
```
status enum: `open | fixed | wontfix | invalid | reopened | judge-rejected`

**⭐ Do this one — it's worth more than the rest of the brief.**
`PATCH /api/v1/bugs/{bug_id}` is literally *"mark it fixed after applying a fix."* So write our verification **back into Replay**. Expose `QA.mark_fixed(bug, ok: bool)` on the protocol; no-op in fixture mode.

Then `verified_by: replay` stops being our word for it and becomes checkable in **Replay's own system** — on stage we open Replay and show the bug flip to `fixed`. Against a panel that scores the gap between demo and build, an external system confirming our claim is the strongest evidence we can produce. Also: `reopened` means a fix didn't hold — feed that to Lane A as a pattern-confidence demotion if there's time.

**Backup we didn't know we had:** `GET /api/v1/projects/{id}/reverse-proxy` returns tunnel status and setup — Replay can reach localhost through their own proxy. That's the fallback if GitHub Pages ever breaks.

# PART 2 — PIONEER  (`docs.pioneer.ai/quickstart`)

| We assumed | Actually |
|---|---|
| Bearer auth | **`X-API-Key: <key>`** — not Bearer |
| bare model names | **namespaced**, e.g. `fastino/gliner2-base-v1` |

- OpenAI-compatible: `https://api.pioneer.ai/v1/chat/completions` (SDK `base_url` = `https://api.pioneer.ai/v1` — it appends the path)
- Anthropic-compatible: `https://api.pioneer.ai/v1/messages`
- Key: pioneer.ai → Settings → API Keys. **Shown once, never again.**

**Our `PIONEER_CHEAP_MODEL` / `PIONEER_STRONG_MODEL` values are invented and will 404.** The instant a key lands:
```
curl -H "X-API-Key: $PIONEER_API_KEY" https://api.pioneer.ai/v1/models
```
Pick a genuinely small model for `cheap` and a frontier one for `strong`, and put the real IDs in `.env`. **If cheap and strong resolve to the same model the entire cost story is fake** — this is the one place a wrong config silently produces a lying chart. Assert at startup that they differ, and log which two models a run actually used into every record's `model` field.

The router/adaptive-routing docs are not on the quickstart page — check `agent.pioneer.ai/routers` or ask Kelton, who is here. `PIONEER_ADAPTIVE=true` is our guess at the toggle; verify before claiming adaptive routing on stage.
