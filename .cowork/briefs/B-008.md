## The bug
`docs.pioneer.ai/quickstart` says `X-API-Key: <key>`. **It is wrong, or stale.** The live Inference page in the Pioneer console shows their own cURL sample as:

```
curl -X POST "https://api.pioneer.ai/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-api-key>" \
  -d '{"model": "pioneer/auto", "messages": [...], "stream": false}'
```

**`Authorization: Bearer`, not `X-API-Key`.** Change it in `live_pioneer.py` and the 403 should clear. Test with one curl before touching anything else.

Worth noting for later: this is the second time today a sponsor's published docs disagreed with their live console. Trust the console.

## Model IDs — also now known
`pioneer/auto` is real and it **is their router**: *"routes each request to the cheapest model that still meets your quality bar, so you save money without picking a model per call."* The console shows **94 models and 1 router**.

Configure the tiers like this, because it uses Pioneer for what it's actually good at:
- **`cheap` = `pioneer/auto`** — the warm path is applying a fix-pattern we already verified. That's easy work; let their router find the cheapest model that clears the bar. This is Pioneer's product doing its job inside our loop.
- **`strong` = an explicit frontier model** — the cold path is reasoning about an unseen root cause. Pin it so the cold cost is stable and the comparison is fair.

Get the frontier ID from:
```
curl -H "Authorization: Bearer $PIONEER_API_KEY" https://api.pioneer.ai/v1/models
```
`PIONEER_STRONG_MODEL` is deliberately blank in `.env` — fill it from that list. **Keep the same-model refusal guard on.** If `pioneer/auto` happens to route to the same model we pinned for strong, the chart lies; log the *resolved* model from each response into every record's `model` field so we can prove they differed.
